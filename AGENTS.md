# Working on Koharu

Koharu is a local-first manga translator: a Rust workspace with a TypeScript interface, shipped as a desktop app. This file holds durable decision rules only. Architecture, file layouts, crate and helper names, model inventories, commands, and anything else a refactor can change belong in crate READMEs and the docs. Normal Rust, TypeScript, testing, formatting, and Git practices are assumed.

## Booharu

This repository is Booharu, a personal Windows fork of Koharu. The rules below are upstream's and still apply; this section is the fork's own and wins where the two differ.

- The goal: add a multi-page chapter, press one button, and get a very passable scanlation (clean, translated, lettered) with no further input. Hand edits stay possible afterwards and always win over automatic choices. Every feature must also work on its own for someone who never uses the automatic run.
- Booharu stays on Koharu as its base. Koharu releases are merged from upstream's real history into `main`, the fork's copy of Koharu, and then from `main` into `booharu`. Where Koharu and Booharu fix the same thing, keep Koharu's fix.
- Keep edits to upstream files small and Booharu's own code in modules of its own, so the next Koharu release applies with few conflicts. An edit to an upstream file is a hook call or a mount line where it can be, and carries a comment starting with `Booharu:` (`/// Booharu:` on a field), so a search for `Booharu:` lists every touch point. Keep upstream signatures: add a setter or an optional field, never change a constructor such as `Tools::new`, and upstream's tests and examples compile untouched.
- Rust: `crates/booharu-core` holds what Koharu's pipeline hooks call (settings types, the attribute registry, shared types) and depends only on koharu-scene, koharu-config and light crates, never on koharu-pipeline, koharu-agent or koharu-desktop. `crates/booharu` holds feature logic and may depend on `booharu-core`, koharu-pipeline, koharu-scene, koharu-llm and koharu-renderer; koharu-pipeline never depends on it. A Koharu crate that calls Booharu code, or holds some of its own, gets one glue module, `booharu`: `src/booharu.rs` in koharu-pipeline, koharu-canvas and koharu-renderer, where it reads the fonts' names in other languages from the faces `fonts/catalog.rs` has on disk, `src/booharu/` in koharu-desktop, and `src/tools/booharu/` in koharu-agent, declared in `tools.rs`; koharu-pipeline's scheduler keeps the run policy in a second one, `src/scheduler/booharu.rs`, which reaches its private fields. No crate per feature.
- Canvas: Booharu's koharu-canvas code lives in its `src/booharu.rs`. Koharu's canvas enums gain only `Tool::OcrBox`, the O tool, and `Effect::Booharu`, whose `booharu::Effect` carries what a Booharu gesture did to the host, with `Gesture::Booharu` inside the crate; a later Booharu gesture goes in under these, never as another Koharu variant. A first translation typed into a block with none passes, in Koharu's `Typing::commit`, two marked hooks: `booharu::untranslated`, its default look, and `booharu::shown_again`, which in the same step shows again the clean-up of a sound effect kept as art and drops the kept mark. Booharu's canvas settings are one `BooharuSettings`, set by `Canvas::set_booharu`: for now the T tool's text defaults, the default font and colours, and a drawn box's starting fit, Best, so its text grows with the box. The desktop pushes it at startup, to each canvas it makes, and after each save that can change it: `booharu_save_preferences`, the agent's settings saves, and Koharu's `save_preferences`, for the Preferred fonts. A later canvas setting goes into it.
- Interface: components in `packages/koharu/components/booharu/<area>/`, hooks and logic in `lib/booharu/`, tests in `tests/booharu/`, styles in `app/booharu.css`, which `app/layout.tsx` imports after `globals.css`; upstream components get one mount line each. Strings go in `public/locales/<lng>/booharu.json`, merged over `translation.json`, as `booharu.<area>.<key>`, `history.steps.<label>` for an edit label, or `tools.<tool>` for a Booharu tool's name, where Koharu's tool rail looks it up. Each change adds all 12 languages, with each language's own plural forms, and leaves `translation.json` as Koharu ships it. A language's file may also override a Koharu key at Koharu's own path, only in that language and only where its text must differ, such as to say Booharu or to add a plural form Koharu's file lacks; an override never copies Koharu's text. Koharu's `FontPicker` takes Booharu's optional props, the favourites, Favorites only and local names, which `useBooharuFontPicker` gives and each mount spreads, and `noneLabel`, a leading row standing for no family; its arrow keys and Enter are built in. A command that writes one setting on its own, such as a font's star through `booharu_set_font_favorite`, runs in turn with the interface's section saves through `queueBooharuWrite`, so none of those saves puts back the value it read before; the agent's `booharu_set_settings` saves only the section it changes, in one read and write under the settings file's lock, so it never undoes either.
- Names: crates `booharu-*`, modules `booharu`, desktop commands and agent tools `booharu_<verb>_<noun>`, edit labels `booharu_<action>`.
- Settings: one `koharu_config::Section` per area in `booharu-core`, a `[booharu-<area>]` table in `~/.booharu/config.toml` and a field of `BooharuPreferences`, which `booharu_get_preferences` and `booharu_save_preferences` read and save whole; the agent's `booharu_set_settings` changes one section through `BooharuPreferences::save_section`, which saves it alone, a table in it only in the keys named, a key it held set to null removing it. Defaults live in Rust with `#[serde(default)]`, and only overrides are written. A bad value fails closed: it is refused, never saved, and a bad stored value is an error, never replaced by its default. Secrets go only through `koharu_config::secrets`. Never a second copy of an upstream setting, never a field in upstream's `Preferences`, and no migration of older settings. `[booharu-lettering]` holds the default text look, `default` {fill, stroke, stroke_width} and `detect_colors`, and the lettering categories' `auto` (Pick fonts automatically, off), `categories` ({family, bold, italic} for each category given its own font, with no blank family and no entry setting nothing; none to start with), `small_text` (0.012, above 0 and at most 1) and `model_confidence` (0.6, from 0 to 1), and the sound effects' `sfx` (`skip`, the default, `inside_bubbles` or `translate_all`) and `subtitle` {`family` (none for the default font, never blank), `size` (0.015 of the page's shorter side, above 0 and at most 0.1), `fill` (black) and `stroke` (white), neither unset}, whose outline, a ninth of its size, isn't stored, and `[booharu-fonts]` the font picker's `favorites`; the default font is no Booharu setting but the first of Koharu's Preferred fonts. `[booharu-runs]` holds the Run menu's `presets`, each a `name` and its `stages`, which set the menu's stage switches, Read chapter's among them, and start nothing, the run policy, `retries` (0 to 5), `on_page_failure` (`continue` or `stop`) and `order` (`pages` or `stages`), and `finish_sound`. `[booharu-reading]` holds Read chapter's `model` (a model reference, never blank; none for the translation model when it can read), `ask` (true, whether the Context tab asks before reading) and `pages_per_request` (20, from 1 to 40), whose rows follow the translator's in Settings > Pipeline. `[booharu-qc]` holds the quality check's `min_size` (0.01, the smallest readable drawn text as a share of the page's shorter side, above 0 and at most 0.1); the check has no switch to turn it off. `[booharu-start]` holds `fresh_start_note_seen`, which dismissing the first-start note sets alone, in turn with the section saves through `queueBooharuWrite`. Settings join Koharu's tabs by topic: the text look, the lettering categories, Apply and the Sound effect subtitles card, its size as a percentage of the page's shorter side, under Typesetting, colour detection, the Sound effects mode and the quality check's smallest readable text, as a percentage of the page's shorter side, under Pipeline; `openSettingsSection` takes a link to a section, opening Settings first from the editor. A topic of Booharu's own gets a tab after Koharu's, listed in `booharuTabs` (`lib/booharu/settingsLink.ts`) and `components/booharu/settings/BooharuTabs.tsx`, with its name at `settings.tabs.<tab>` in `booharu.json`: Runs, for `[booharu-runs]`.
- Booharu-only data on a scene layer goes in its attributes under the `booharu` namespace, each key a type in the registry `booharu_core::attrs`; data the renderer must read becomes a real scene field. The keys are `lettering` {category id, source: user or model, confidence from 0 to 1, role: the block's Koharu role before a category picked by hand changed it} on a block, `auto` {origin, source, text, style, marks: [{start, end, style}] the words the Translation stage marked for emphasis, by UTF-8 byte offsets into the text it wrote, kept: whether Booharu hid the clean-up to keep the original art, split: whether it's a half of a block split by hand, whose box a hand cut though it carries detection's record} (the hand-edit record), `qc_ok` [`<check>@<fingerprint>`, a check id or `glossary:<term source>` and the layer's fingerprint as it was marked] and `flags` [{kind `review`, message}] on a block or a text layer, `read_note` and `review_note` (text), `sfx_subtitle` {block} on a sound effect's subtitle, `original_scan` (true) and `skew` {x, y} in degrees. Write them only with the registry's ops inside the action's one edit, or, on a layer that edit adds, as its registry type's value under its key in the `AddLayer`, as a subtitle is added, leaving locked layers out and saying how many; a reader takes a bad value for absent.
- Box tools: each box action builds its one edit in `crates/booharu`'s `boxes` module, which the desktop commands and the agent tools share, as koharu-agent can't call koharu-desktop. The interface defines each per-box action once, with its label, when the selection enables it and what it calls, in `lib/booharu/boxActions.ts`, the one list the Story row menu, the Edit menu, Box details and later the canvas's right-click menu show; Box details shows the sections listed in `components/booharu/details/sections.tsx`, each for the texts its `shows` takes, and opens on one when an action names it. A later action or section is one more entry. A selection carries its page's lettering as the views last read it (`lettering`, through `useLettering`), undefined while it isn't known, which leaves Add subtitle off. A reviewer's note is the `review_note` attribute on a block or a text layer, set or cleared by one `booharu_set_review_note` edit; a locked layer refuses it, as Koharu refuses attribute writes there. The Detection stage marks each block it makes with Koharu's `c2pa.detection` attribute, and a block made by hand, such as with the O tool, is made with no `c2pa` attribute, so a block without `c2pa.detection` is hand-made; a split's halves keep the record they were copied with, so the split writes `auto.split` on both, which only Detect again reads (`protect::keeps`), to keep them: a split writes no wording or look of its own, so Apply restyles them as any other box. The split also drops the halves' `c2pa.ocr` and `c2pa.translation`, which recorded reading and translating the whole block, so until its run writes them again the planner plans both for the halves, the quality check takes neither half for one read as empty, and wording typed into one counts as typed by hand, which that run leaves alone, as it does a half of a translated block whose clean-up was hidden by hand, which reads as hidden by hand on a block with none (`sfx::hand_kept`); undo gives the block its records back.
- Hand edits: `booharu.auto` records what Booharu's automatic steps wrote, in the same edit as the write: the Recognition hook the hash of each source it reads, the Translation hook, on every translation it writes, the hash of the text, the style values it left and the word marks its emphasis set (`auto.marks`, read only while the text is still the one hashed: `Auto::trusted_marks`), and Apply and a change of category the style they wrote; a line given back, Reset to lettering default and a split drop the marks, Apply takes off the keys it clears from the words, and the words edit (`booharu::words`, `booharu_style_words`) leaves the record as it is, so a word it styles is a hand edit. Hashes are stable short hashes of the trimmed text, never Rust's `DefaultHasher`. `booharu_core::edited` tells which parts were changed by hand: the source or the text, when its hash differs, or with no record when no `c2pa` action wrote it; the style, when a recorded key differs, a span carries a mark for one but for a value the run's own marks set there and that still holds, size never counting, or the record's origin is `agent`, as after the agent's Apply; and drawn, a block without `c2pa.detection`, so not a split's halves, whose cut (`auto.split`) counts only for Detect again. Text typed by hand has no record, so it counts as hand-made. Apply, and any later automatic step that changes text already made, leaves hand-edited blocks alone unless told to include them; a later stage's automatic write records its own keys in `auto` too.
- Default text look: new text with no family of its own gets a copy of the first Preferred font, so finished pages keep theirs when the list changes: every translation a run writes, a first translation typed by hand and the T tool's text; with no Preferred font, none is written. With `detect_colors` on, Booharu writes no colours, so the colours Koharu measured, or copied from the source for a typed translation, stay; off, the default colours replace them, except that a sound effect keeps Koharu's legibility outline when the default sets none. The T tool's text always gets the default colours. Booharu restyles translations already made only through Apply (`booharu_apply_text_style`), one edit that never recolours with detection on, Reset to lettering default, and, while `auto` is on, a change of category, which changes only their font. Translating again keeps a box's look as it was set, by hand or not (D13), while Koharu's placement sets its frame, fit, transform and direction again.
- Lettering categories: `booharu_core::lettering` holds the 18 `LetteringCategory` ids in Settings' order, 0.0.4's fifteen (`normal_dialogue` to `menacing`) then `handwritten`, `sign` and `electronic_voice`; the interface lists them in `lib/booharu/categories.ts`, which doesn't compile without each, and names them at `booharu.lettering.categories.<id>`. A category's font (`LetteringSettings::category_font`) is its own entry, else Normal Dialogue's, else none, which keeps the default look's font; an entry without a family takes Normal Dialogue's family, else a copy of the default font. It sets only a translation's `style.chars` `family`, `weight` (700 or null) and `italic` (true or null), never other keys nor marks, so word styles survive it. A block's category (`effective`; only blocks have one, so the T tool's text gets none) is, with its reason: a user's label (`user`); a model's label of a presentation category, `title`, `phone_text`, `sfx`, `handwritten`, `sign` or `electronic_voice`, at any confidence (`model`); `sfx` for Koharu's sound effect, `Role::Sfx` (`sfx`); a model's label of a delivery category, `thoughts`, `weak_shout`, `moan`, `whisper`, `shy`, `crying`, `menacing` or `shout`, at least `model_confidence` sure, none counting as sure (`model`); `small_text` when its glyphs, the size detection measured on its source, else 0.0.4's estimate from its frame and wording, are under `small_text` of the page's height, never without either (`small_text`); its balloon's shape, round `normal_dialogue`, rectangle `narration_box`, spiky `shout` (`shape`); else `floating` (`floating`). A model's label of another category never wins. `booharu_core::shape` classifies an outline as 0.0.4's `bubble_shape.rs` did, over kurbo paths flattened and simplified at 0.1% of their length: spiky with at least 5 dips deeper than 8% of the smallest rotated rectangle's short side and a solidity under 0.90, else a rectangle with a rectangularity of at least 0.90, else round. A block's balloon is the one holding it, else the smallest on its page whose outline holds its source's centre, as for a box drawn by hand; the shape is worked out when asked, never stored. Booharu's own steps write a category font only while `auto` is on, and with it off write the look above and nothing more: `styles::new_translation` gives it in place of the default font to a run's translation, whose record counts its keys as automatic, and to one typed in Story, through the agent or on the canvas, each through `lettering::auto_category`; Apply gives it to each translation, keeping those keys' marks; and a change of category gives it.
- Changing a category: `booharu::lettering::set_category` builds one edit labelled `booharu_set_lettering_category` for any number of blocks, which the desktop command `booharu_set_lettering_category` (the user's choice, `None` for Automatic) and the agent's tool of that name (a model's) share: each block's new label, or none for Automatic, and while `auto` is on its translation's new category's font with its record, built even when the label stays, so picking a category again applies a font changed since; one that changes nothing adds no undo step. A user's choice restyles a font changed by hand, and its Automatic clears any label; a model's never replaces a user's label nor restyles a block whose style was changed by hand, and its Automatic clears only a model's label. Either pick is also the block's Koharu role (D4), one `UpdateLayer` in the same edit: `sfx` makes it a sound effect and any other category text, which the sound-effect rule reads at once, the label recording the role the block had before the first pick changed it, which Automatic gives back as it clears the label; Read chapter's labels (`category_ops` with `role` false) never change the role. Koharu frames and outlines a block by its role only at its next translation, a known limit, so Reset to lettering default is how its outline follows at once. A block with no translation that the new label and role make a sound effect kept as art has its clean-up hidden with the kept mark in the same step, and one kept as art that no longer is keeps it hidden until its translation shows it. Locked blocks are left out and counted, and it answers `changed`, `locked`, `kept_user_label`, `kept_hand_edited` and `untranslated`. `booharu_get_lettering` answers each block of a page: its category, reason, label, balloon shape with its measures (rectangularity, solidity, spikes), and whether it was changed by hand. The agent's label tool refuses the four categories a label never gives, `normal_dialogue`, `floating`, `small_text` and `narration_box`; `booharu_get_text_styles` (read-only) answers the look, each category's resolved font with where it comes from, and blocks' categories; and `booharu_apply_text_style` takes a `category` or a `shape` to letter every block as, whether `auto` is on or not, recorded with origin `agent`. In the interface, Settings > Typesetting's Lettering categories card (`components/booharu/lettering/`) has the switch, a searchable category picker, the chosen category's font, whose leading row, "Same as Normal Dialogue" or for Normal Dialogue "Same as the default font", removes its own family but keeps its own bold and italic, with bold and italic, which give a category without an entry one of its own with no family, so it still follows Normal Dialogue's, the categories with their own font, Suggest fonts, which fills only categories without one from 0.0.4's starting list (NFKC, without spaces, ignoring case, catalog fonts counting as available) and gives the three new ones none, and Apply. Per box, the Story row's category tag, a Layers block row's second line, Box details' Lettering section and the `category` box action, Change category, show it, read through `booharu_get_lettering` per page under Story's query key so each change reads it again; their pickers offer Automatic and the 18, and say while `auto` is off that fonts follow categories only with it on.
- Sound effects: booharu-core's `sfx` holds the rule that the run filters, the planner, the quality check and the commands all call, never a copy of their own. A block is a sound effect when its category as Booharu reads it (`lettering::effective`: a user's label, then a model's, then Koharu's role) is Sound Effect, whether or not Pick fonts automatically is on, and `[booharu-lettering] sfx` says which of them a run translates (`skipped`): none with `skip`, those in a balloon, held by one or under its outline, with `inside_bubbles`, all with `translate_all`; one with a subtitle never, so its translation doesn't come back over the art. An effect a run skips keeps the page's own lettering: no translation, its clean-up hidden and the kept mark (`auto.kept`) written in the same step (`kept_original`, only on a block with no translation whose clean-up shows and that carries no mark), never the given-back record (`styles::given_back`'s, written when Koharu's Translation stage is given its source back), so a clean-up hidden by hand (`hand_kept`) can be told from Booharu's, and one shown again by hand from one Booharu never kept (`hand_shown`). A translation, typed or written by a stage, a line given back, and a join that shows the joined block's clean-up or writes it a translation drop the mark, and a translation shows the clean-up again; a split's halves keep the clean-up as it was, and so the mark, or a line given back its record (`styles::given_back`'s, as Koharu's stage records nothing there), so neither half reads as a clean-up hidden by hand, which the split's run would leave alone. The subtitle, `booharu_add_sfx_subtitle(block, text)`, the desktop command and the agent tool alike through `booharu::sfx::add_sfx_subtitle`, is a text layer named `SFX subtitle` whose `booharu.sfx_subtitle` names its effect, added right after the effect in reading order: horizontal, aligned to the start, with no fit, 12 sizes wide and 2.8 high, a third of a size away, left of a vertical source and below any other, on the other side when that leaves the page, then moved onto it, in `[booharu-lettering] subtitle`'s look; the same edit, `booharu_add_sfx_subtitle`, takes the effect's translation away and hides its clean-up with the kept mark. Its words are the ones given, 1 to 500 characters, else the effect's translation; with neither, the answer is a Translate run on the effect alone with `subtitle_run` (`booharu::sfx::subtitle_run`), whose write puts the model's answer in the subtitle, or a refusal when the effect has no words read either, which that run couldn't send. An effect with a subtitle answers that one, and a block that isn't a sound effect, is locked, or has no source box to put one beside is refused; a subtitle run's write leaves as it is an effect that got a subtitle or lost its box meanwhile, or whose answer is its source, and, counted, one locked meanwhile or given a translation meanwhile, typed or by another run, which stays as fixed by hand (D1), so Add subtitle then makes the subtitle from it. In the interface, Settings > Pipeline's Sound effects row (`components/booharu/pipeline/SfxSection.tsx`, one mount line in `PipelinePreferences.tsx`) saves the mode as it's picked, and the Add subtitle box action, on one unlocked block whose page's lettering says `sfx`, selects the subtitle or says the effect is being translated for it. A first translation typed on the canvas into an effect kept as art shows its clean-up again and drops the mark in the same undo step, as Story's typing does: `Typing::commit` appends, through a marked line, `koharu-canvas` `booharu::shown_again`, which finds the block on the page and answers `sfx::shown_again`, `kept_original`'s inverse (the clean-up shown when hidden, and the record without the mark, cleared when nothing else is left in it, as `styles::typed` writes it); a block with no mark gets Koharu's ops alone, so a clean-up hidden by hand stays hidden.
- Reset to lettering default (D13): booharu-core's `resolver::lettering_default` works out from the scene alone, with no model call, the look a box would have from scratch: for a translated block, the look its first translation got, at its current size, Koharu's placement colours and outline measured from its source (`koharu_chars`, a copy of `stages/translate/placement`'s rules, which a parity test in koharu-pipeline's Booharu tests keeps in step) under Booharu's default look, with its live role and, while `auto` is on, its category's font; for a subtitle, the subtitle look; for any other text layer, the T tool's default look; an untranslated block has none. `booharu::styles::reset_lettering`, one edit labelled `booharu_reset_lettering` that the desktop command and the agent tool of that name share, gives each unlocked layer only the ops it needs: every one of the eight look keys and the border method, null where the default sets none, its words as one unmarked span when a span has marks, and for a block its record, automatic, with the new look; never its words, size, frame, transform, direction, alignment, clean-up or role. It answers `changed`, `locked` and `untranslated`, and the box action of that name, on while a selected text is an unlocked text layer or translated block, toasts them.
- Pipeline hooks: `Pipeline::run` puts the run's snapshot of Booharu's settings in `PipelineConfig.booharu`, never saved, whichever way the run was queued, and the stages read only that; for a run that translates, the same hook puts the chapter's notes after its Instructions (see Sending the chapter's notes). Its `runs`, the run policy from `[booharu-runs]`, is set only there, so the Run button's, the agent's and MCP's runs all follow it; `None`, as `PipelineConfig::default()` holds it, is Koharu's own behaviour, which only a run made without `Pipeline::run`, as in the scheduler's tests, keeps. It keeps two flags from the config the run was queued with, which only Booharu's Rust callers set and no setting holds: `redo`, Redo boxes taking hand-fixed boxes too, and `subtitle_run`, a Translate run subtitling the sound effects it names; the interface's `runPipeline` never sets them. A section the snapshot can't read refuses the run, as it refuses a typed translation's edit, and the canvas keeps the settings it had. The Translation stage's `written()` adds the look and the record after placement's op, and the Recognition stage adds the record beside its source write, each through koharu-pipeline's `booharu` module.
- What runs leave alone (D1, D7): booharu-core's `protect::left_out` says why a stage leaves a block out, for every run alike: `locked`, a block that is, or is in, a locked layer, at every stage, and when cleaning one whose clean-up is locked too, which nothing lifts; `hand_fixed`, when reading a source corrected by hand, and when translating a translation written or fixed by hand (`edited().text`) or a clean-up hidden by hand on a block with none, which only a run's `redo` lifts; and `sound_effect`, when translating an effect `sfx::skipped` keeps as art, checked before `hand_fixed`, which no redo lifts and a subtitle run lifts for the effects it names. Detection and Read chapter leave nothing out by it, and cleaning again never asks. koharu-pipeline's `src/booharu/filters.rs` applies it through marked lines in each stage: `Left::sent` narrows what Recognition and Translation read and send; `Writing` checks again against the project as each write finds it, so a block locked or fixed by hand while the model ran stays as it is, counted, rather than failing the page's edit or being written over; and a translation, or a cleaning, writes `kept_original` on the effects Translation skips, so their clean-up stays hidden whichever runs first, even on a page with no line left to send (`Left::unsent`). Detect again (`stays`, `protect::keeps`) keeps a locked layer, a block changed by hand (source, translation or style, or drawn), cut from a block split by hand (`auto.split`), whose clean-up was hidden by hand (`sfx::hand_kept`, never by Booharu's kept mark nor by a line given back) or shown again by hand while it carries the kept mark (`sfx::hand_shown`, which `kept_original` leaves alone too), labelled by a user, given a reviewer's note or subtitled, a panel or balloon Koharu's Detection stage didn't make, any text layer, and whatever holds one of those; it adds no new block whose source lies over a kept one by at least half the smaller area, nor a new panel or balloon that held only such blocks, and numbers the rest again from 0 within each parent. New layers go in front of the kept ones, as Koharu adds them at the top of the page, so kept layers come after them in reading order: a known limit, which dragging them in Layers puts right. Each page stage tells `skipped` {run, page, stage, sound_effects, hand_fixed, locked, blocks} (`Event::Skipped`, a marked variant) for a page once its edit is in, when a count is above 0 and the run wasn't stopped, `blocks` being whether the run named blocks: Translation all three counts, Recognition `hand_fixed` and `locked`, Inpainting `locked`, and Detection the blocks it kept, as made or changed by hand or as locked. Koharu's store's fold changes nothing for it (a marked case in `lib/store.ts`), and `lib/booharu/jobs.ts` adds the counts to the run's record, from which one toast as the run ends, told live, says what it left alone: the hand-fixed ones by stage, the locked ones once a page, worded as Detection's when only it met them, and the sound effects kept as art only for a run that named blocks, with how to translate one. A recognition task reads together only pages of runs with the same `redo` (`scheduler::booharu::alike`, a marked line in the scheduler), as it reads every page with its first page's settings. The agent's Koharu run tool says what runs leave alone through one marked line (`booharu::RUN`), and its wait tool's description explains `skipped`.
- Redo boxes: `booharu::redo` counts the blocks named for reading, translating or cleaning again (`count_redo`, `RedoCounts` {ready, hand_fixed, locked}, through `left_out`) and builds one ordinary run on the unlocked ones (`redo_targets`, `Redo::request`), without the hand-fixed ones unless they're taken on purpose, with the saved pipeline settings and `redo` set to that choice; with none left there's no run. - Run policy: a stage task's failure carries a class, read in `stages::run()` from the error chain before it's worded: Invalid (`Error::Invalid`, or an edit the project refused), Write (any other scene error, which ends the run whatever the policy), Load (a model that couldn't load, which another try with nothing freed can't help), HostedRetried (a hosted 429 or 5xx, which koharu-llm already sent again) and Retryable (anything else: a dropped connection, the time limit, a broken, blank or short answer, a model's own error, a panic). A failed recognition batch is none of its pages' own: each page is read again alone, after its wait when it's tried again, or at once with no try counted when it wouldn't be (a refused edit, no tries left), so only a page that fails alone is given up on or stops the run. ## Product

- Models run on the user's machine. Pages and text leave it only through a hosted provider the user chose.
- Editor behavior that is not already specified matches Photoshop or Clip Studio Paint. Ordinary editing happens in the app, not through an export and re-import round trip.
- Desktop API keys and sign-in tokens are stored encrypted, with the key kept in the OS credential store. Do not fall back to a project environment file.

## Changes

- Never add backward compatibility, except that a project file a release wrote keeps opening. When an API, schema, file format, configuration, or ownership boundary changes, delete the replaced form: no alias, forwarding layer, compatibility parser, upgrade decoder, stub, or disabled flag.
- Changing a released project format ships an upgrade to the new one, which leaves the file as it was if it fails. A format no release wrote gets no upgrade.
- Prefer a coherent ownership redesign over cosmetic renaming. Defaults and provider-specific behavior belong to the component that owns them, not to a central list of special cases.
- Make the smallest change that solves the problem. Leave unrelated configuration, documentation, generated files, and workflows alone. A feature does not land beside drive-by cleanup.
- When two changes implement the same workflow, keep one and extend the existing command or configuration.
- If the code you are changing has moved, rebase onto its new owner. Do not port a patch onto a deleted tree.
- Invalid configuration and model output fail closed. A project file fails to open only when it doesn't parse, isn't this app's format or version, or would crash a reader; its structure is kept by the operations that write it, not checked again. Do not add a repair or defaulting layer that can change meaning.

## Code

- Write the smallest code that does the job. Inline a helper with one caller, keep a small module in its parent, and do not wrap a type without adding a responsibility.
- Reach for a crate before writing code: a well-known external crate first, then one in this repository. Hand-write only what no crate covers, and prefer a cross-platform crate to per-platform branches.
- Keep safe public APIs apart from unsafe FFI, dynamic loading, and build integration.
- Do not hand-edit generated or derived source. Change its input and rerun the generator.
- Comments explain ownership, invariants, upstream mapping, or a deliberate divergence. Do not narrate straightforward code.
- Do not commit credentials, model weights, datasets, generated outputs, or machine-specific files.
- Search with `rg`, never `grep`.

## Interface

- User-visible strings go through the translation function and the locale files. Hardcoded English in a translated surface is incomplete.
- An interface language's display name is that language's own name in every locale.
- The translation-target language list stays in the active UI language. Drop a country name unless the entry is a real variant.
- Do not show status the current selection already implies. Do not add a second job kind, cancel path, or counter for an operation an existing command covers.
- Use the existing control library for standard interaction. Commit on selection or an uncanceled drop, never on focus or hover. Ignore a canceled drag. A shortcut never steals keys from a focused control.

## Models

- A port stays structurally traceable to a commit-pinned upstream implementation. Preserve checkpoint-affecting names, construction order, parameter paths, tensor layouts, execution order, and postprocessing semantics. Explain each intentional divergence next to the affected code.
- Missing or unexpected weights mean an architecture or parameter-name mismatch. Fix that before changing the loader.
- Every model has the same public lifecycle, with model-specific inputs and outputs. Network and weight loading stay apart from preprocessing, postprocessing, slicing, and result types. Do not add pass-through types or layers.
- Accept a device at the model boundary and convert it once. Create token IDs and index tensors on the model device; a CPU tensor used against accelerator embeddings is a defect.
- Use the established loading paths unless they are proven insufficient.
- Disable gradient tracking during inference.

## Performance

- Optimize and benchmark on the actual target device with representative inputs. Load assets and warm models outside the measured region, and account for asynchronous accelerator execution.
- Remove redundant transfers, synchronization, allocations, and per-pixel host loops before adding concurrency or caching.
- Report the device, input size, baseline, result, and correctness difference.

## Verification

- Run the smallest relevant check or focused test once, in the debug profile. Run full suites, other profiles, or end-to-end tests only when asked.
- Add a test only where it protects a real regression boundary. Do not lock a translated phrase, a language display name, a registration string, or a one-line behavior the owner can read. Do not add a second harness for behavior existing tests cover, a test of a compatibility shim, or a benchmark nobody asked for.
- A model port needs a structured comparison with upstream on identical inputs: shapes, ranges, boxes, scores, masks, and ordering. A green build is not that comparison.
- A UI change needs a screenshot of the affected state. For truncation, include a long label.
- A green check is not acceptance.
