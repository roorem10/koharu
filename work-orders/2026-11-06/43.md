# WO-43: Fix text in joined bubbles jumping or overlapping after dragging (issue #17, upstream 986)

Symptoms:
1. Text too tall for its bubble stacks up and jumps to another spot. Undo/redo sometimes makes it behave.
2. Two connected speech bubbles: drag one detected box over the narrow neck between the bubbles and release; both boxes end up overlapping or misplaced. 100% reproducible per the reporter.
3. Stretching the box sides further can make the text vanish.

Likely cause, from an earlier code read: bubble text doesn't use its own box. `resolve_balloon_flows` (`crates/koharu-renderer/src/renderer.rs`) lays out every text layer that `FlowsIn` the same bubble by splitting the bubble outline into cells (`flow_cells`), one per text, anchored at the centre of each text's original detected region. Two joined bubbles are often detected as one bubble region, so both texts share it. Moving a box doesn't move its anchor, so the split and the drawn position don't follow the drag. When text is too big for its cell, the fit search picks very different sizes for small geometry changes.

Existing workaround: the "fix boxes in bubble in place" lock button beside Placement turns every box in the bubble into a custom frame at its current spot.

Build the fix:

1. Verify the cause by reading the code, including what a drag commits. Re-verify it's still right on this base, since WO-20 joined split boxes.
2. A dragged box's position must be respected: either re-anchor the dragged box's share to where it's dropped, or drop its `FlowsIn` link when it's dragged outside its cell, whichever is cleanest and is one undo step. The other box in the bubble must not move unexpectedly. Prefer the approach that also fixes symptom 3.
3. Make the fit search stable for tiny geometry changes (symptom 1) if the code read shows it's an actual cause; otherwise explain.
4. Keep "incremental reuse must match a full render", and all outputs must agree (AGENTS.md).
5. Tests with the renderer's existing test approach: two texts sharing a bubble with one dragged across the neck, too-tall text stays in the same place across tiny geometry changes, box stretched wide keeps text visible.
6. No new feature, so no new agent action; `set_geometry` must behave the same way as a drag. Check that it does.
