# WO-34: Speaker per text box, and per-box context sent to the translator (issue #53, upstream 1276, goal #54)

When two characters share a page, the translator guesses who speaks, and in many languages the speaker's gender changes the wording. Box notes (WO-06, `LineContext.box_note`) and Read chapter line notes are also saved but never reach the translator.

Read first: `commands/context/reading.rs`, `commands/context.rs` (`translation_hints`), `commands/notes.rs`, `commands/line_labels.rs`, `koharu-translator` and how segments reach each provider, `components/editor/TextLayerKind*`, `LetteringCategoryLine.tsx`.

Build:

1. **Read chapter returns a speaker per line**: an optional `speaker` in the reading schema, chosen from the series character list. Unsure means blank. Stored on `LineContext` in the sidecar beside the other labels, with its source (model or user), no save-format change.
2. **Show and edit**: the layer row shows kind and speaker together, like "Shout · Mika". The box gets a small Speaker picker (series characters plus None), using the existing control library. A hand-set speaker always wins over the model's, same rule as lettering labels.
3. **Send it to the translator**: each segment in the translate request carries its speaker (with that character's notes) and its box note or Read chapter note, through the existing single translation path. With nothing set, the request must stay byte-for-byte as today. Add a test for that.
4. **Agent actions:** read and set a box's speaker, and set a box note.
5. Tests: schema parsing with and without speaker, hand-set speaker not overwritten by a re-read, request unchanged when empty.
