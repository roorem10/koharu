# WO-33: Keep names and terms consistent across chapters (issue #59, goal #54)

A series runs from 6 to over 100 chapters. A name written one way in chapter 3 and another in chapter 4 gets noticed. Today suggested terms stay in the chapter's project until accepted, so the next chapter only sees the series glossary.

Read first: `crates/booharu-context` (`series.rs`, `chapter.rs`, `sidecar.rs`), `commands/context.rs` (`translation_hints`), `commands/context/`, `components/context/*`, the Fix a term everywhere path (WO-18).

Build:

1. **Save terms to the series:** a function `save_chapter_terms_to_series` that adds the chapter's used suggested terms to the series glossary as unlocked entries, plus a **Save terms to series** button in the Context tab. Setting, on by default, to run it automatically when a chapter is marked done or when the auto run ends (a sibling branch owns the recipe; expose the function and don't wire the recipe).
2. **Conflicts:** same source with a different target than the series has aren't added; they show once in the Context tab to choose (keep series, use chapter's and update series, or leave).
3. **Characters:** new characters from Read chapter are added to the series characters, with notes such as pronouns only when the model is sure.
4. **Learn from hand edits:** when a hand edit to a translation changes how a known glossary term or name is written, offer once, non-modally, "Use this everywhere and save it to the series" reusing Fix a term everywhere. Put the detection in a pure, tested function and keep false positives low.
5. Works the same for chapters run step by step. Series storage stays atomic in the existing way; handle several projects using one series without losing entries.
6. **Agent actions:** save suggestions to the series; read and edit series characters.
