# WO-32: OCR check with the vision model (issue #58, goal #54)

A wrong character in the source becomes a wrong translation, and nothing later in the run can fix that. OCR models give no confidence (`OcrAnalysis.confidence` is empty in `koharu-pipeline/src/stages/ocr.rs`), but Read chapter already sends page images and OCR text to a vision model.

Read first: `commands/context/reading.rs` and its structured schema, `commands/context.rs`, `commands/line_labels.rs`, `components/editor/LineContextCard.tsx`, how OCR provenance is kept in Scene (AGENTS.md: translation doesn't drop OCR provenance).

Build:

1. Read chapter also returns a corrected source text for lines where the OCR clearly doesn't match the image (missing or wrong characters, wrong column order), with a short reason. One more optional field in the reading schema, enforced through the provider's native structured output. No new prompt path.
2. Store suggestions in the project sidecar next to the other line labels.
3. **In normal runs:** corrections show as a suggestion on the box (OCR text, suggested text, reason) with **Accept** and **Dismiss**. Accepting is one undo step and keeps the original OCR recoverable; an already translated line is marked out of date in the existing way.
4. **Automatic apply:** a function `apply_ocr_corrections` that applies them before translating, one undo step per page, marks "OCR corrected", keeps the original. Exposed for the auto-run recipe (a sibling branch owns the recipe; don't wire it) and enabled by a setting in Translation preferences (off by default until the auto run uses it).
5. **Never** change source text that was typed by hand. Find how hand-typed source is distinguished; test this rule as a pure function.
6. No vision model: the step is skipped and a clear reason recorded.
7. **Agent actions:** read OCR suggestions, accept one or all.
