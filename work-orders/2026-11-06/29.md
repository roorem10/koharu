# WO-29: Check cleanup for leftover text and clean again (issue #56, goal #54)

After cleanup, people check every page by eye for leftovers: outline halos around letters, furigana, strokes outside the mask. Automate it.

Read first: `koharu-pipeline/src/stages/detection.rs` (`write_mask`), the inpainting stage, `commands/cleanup.rs` and `commands/cleanup/`, `components/cleanup/*`, `components/editor/CleanupQueueBar.tsx`, `commands/qc*`.

Build:

1. **Check:** a pipeline-side function that composites original plus Cleanup layer for a page, runs the existing text detector on it, and intersects results with the page's cleaned areas (the original text areas, slightly grown). Runs locally through the existing accelerator admission lane; follow AGENTS.md's pipeline rules (snapshot in, patch out, one committed result per undo step, stale patch rejected).
2. **Second try:** where leftover text overlaps a cleaned area, grow the mask there and clean that area again, once. Setting in Cleanup preferences: **Model for the second try** (default: same as the normal cleanup model).
3. **Report:** still there after the second try: a new QC check **Leftover text in cleanup** with the area outlined on the canvas. Clicking it jumps to the area with the cleanup brush selected. Detector hits that don't overlap a cleaned area (probably speed lines or patterns) are never cleaned; list them only as low-priority items if that's cheap, otherwise drop them.
4. **Hand work wins:** never repaint anything the user painted by hand on the Cleanup layer. Find how hand strokes are distinguished from generated cleanup today. If they aren't, record the hand-painted areas in the sidecar or the least invasive place, or skip any area that's changed since the last automated cleanup, and say which you chose.
5. **Entry points:** a **Check cleanup** button for one page or all pages, as a normal job with existing progress and stop behaviour. Don't wire it into the auto-run recipe (a sibling branch owns that); expose a function with a clear signature it can call.
6. **Agent actions:** run the cleanup check on chosen pages (`check_cleanup`) and read its results; the read works in read-only mode, the run doesn't.

Put the geometry decision (overlap, growth, what counts as leftover) in a pure, unit-tested function.
