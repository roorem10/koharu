# WO-45: Fix the O tool reading text that isn't there on blank areas

Noted during 0.0.3 testing: with the OCR box tool (the O tool, WO-07), reading a box drawn on a blank area returns invented text. OCR models tend to hallucinate on empty input.

Read first: `crates/koharu-app/src/commands/ocr_box.rs`, `components/canvas-tools/ocrBox.tsx`, `components/ocr-box/*`, `koharu-pipeline/src/stages/ocr.rs`.

Build:

1. Before OCR on a hand-drawn box, measure whether the region has any ink worth reading: a pure, tested function using local contrast and the count of dark or light pixels against the local background, robust to screentone. Comparing the crop with the Cleanup layer isn't needed.
2. A blank region doesn't call the OCR model. The box is either not created or created empty per how the tool works today, with a short, translated, non-modal message like "No text found here".
3. Also apply the same check to the model output: if a box's OCR result is one repeated character or punctuation run over a near-blank crop, treat it as empty.
4. Thresholds must not reject faint or thin real text. Pick conservative values and explain them next to the code. When unsure, run OCR as today.
5. Keep **Read again** on an existing box consistent with this. No new agent action; the existing OCR action inherits the behaviour, which you should confirm.
