# WO-47: PSD export: keep effect text boxes as editable text where possible

Noted during 0.0.3 testing: PSD export turns boxes with effects into pixel layers, which needs a closer look. Upstream `#984` (Cleanup layer above text) has a fix ready on the branch `fix/psd-layer-order`; don't redo that.

Read first: `crates/koharu-psd`, the export path in `commands/output.rs`, how the prepared frame feeds PSD (AGENTS.md: one prepared frame feeds presentation, PNG, crops and PSD).

Do:

1. Establish by reading exactly which text boxes become pixel layers and why: outline, double outline, contour, gradient fill, warp, rich text word styles, rotation.
2. Where PSD's native text layer plus layer effects can represent the box faithfully (for example a plain stroke through the `lrFX`/`lfx2` effects data, or a solid fill), write a live text layer with effects, using the cached pixels from the prepared frame so that a viewer that doesn't re-render sees exactly the same thing. Where it can't be faithful (warp, double outline), keep today's pixel output, and also add a hidden editable text layer with the plain text directly above it, so the words can still be edited in Photoshop.
3. Preserve the PSD's correctness for Photoshop and other readers: section ordering, lengths, padding, unicode layer names. Add structural tests in the crate's existing style (parse back what's written).
4. No Photoshop on this PC, so be conservative: if a descriptor is uncertain, prefer the simpler known-good form. State in your summary what must be tested in real Photoshop.
5. Agent action: export is on a sibling branch; no action needed here.
