# WO-28: Fix easy QC problems automatically, and a "Check these first" list (issue #64, goal #54)

After translation, most QC problems are mechanical and can be fixed without a person. What's left should be a short list, so a person can review a chapter in minutes.

Read first: `commands/qc.rs` and `commands/qc/`, `QcCheck`, `components/qc/*`, `commands/ocr_box.rs` (Read again), the Translate again path, `commands/styles.rs`, `commands/lettering.rs`.

Build:

1. **Fix pass**, a native function over QC findings, only on boxes that weren't hand-edited, at most two tries per box:
   - Overflow or too small: tighten hyphenation and line spacing within limits, then widen the box inside its bubble, then ask the translator for a shorter wording with a length target. Shorter wordings always get listed for review.
   - Missing translation: translate that line again.
   - Japanese left in the translation: translate again, telling the model to translate or romanize it; names come from the glossary.
   - Missed locked term: translate again with the term required.
   - Odd font: apply the category style again.
   - Empty source: OCR the box again (WO-07's Read again). If it's still empty, hide the box and list it (probably a false detection).
   Use the existing single translation path and its structured output; do not add a second prompt path beyond the optional instruction it already can carry (extend it minimally if it can't). Put the "what to try next" decision in a pure function with tests.
2. **Every fix is one undo step**, marked "Auto-fixed: reason" in Box details, with the earlier version kept (sidecar or the existing line context, not a save-format change).
3. **"Check these first" list** at the top of the QC tab after a run, grouped by page: problems still open, auto-fixed boxes, and unsure guesses (low-confidence lettering labels; leave clear extension points for speaker-unsure and OCR-corrected). Click to jump using the existing page-switch path. **Looks good** marks it done, using the existing QC "OK" rather than a new state.
4. **Run summary data:** fixes made, items left, requests used, available to the run summary that the auto run shows (a sibling branch builds the auto run; expose a function it can call, and call it from the button here).
5. **For manual users:** a **Fix automatically** button in the QC tab, for one box or for every problem, as a normal job with the existing progress and stop behaviour.
6. **Agent actions:** read the QC list, run the fix pass on chosen boxes or pages, mark an item OK. Read-only mode only exposes the list.
