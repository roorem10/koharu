# WO-39: Agent tab and MCP coverage, part 2: output, runs, rich text, project (issue #51)

The in-app Agent and the MCP server should be able to do anything a user can do through direct tool calls. Both use `KoharuHost::tools()` in `crates/koharu-app/src/commands/agent/host.rs`. Add the missing actions below, each calling the same native function the UI's command uses (no second implementation), staying revisioned and undoable, and hidden in MCP read-only mode if they edit.

Add:

- Export, translation scripts (export and import) and page naming (WO-13, `commands/output.rs`)
- Run presets, retries, keep going and stage-at-a-time options (WO-14, `commands/runs.rs`), read and change. Starting a batch of chapters if that's safe
- Rich text runs read access and anything `style_words` doesn't already cover (WO-11, `commands/rich_text.rs`)
- Project and library actions: list, open, rename and duplicate where it's safe. Opening a project from the agent has to handle a run in progress and unsaved state the same way the UI does. If an action can't be made safe, leave it out and explain why in your summary. Deleting projects is not included

Export writes to disk chosen by the caller: follow what the UI's command allows, and don't let MCP read-only mode reach it.

Keep the host file manageable: put new tools' argument types and handlers in the owning feature's module, like `commands::emphasis::agent` and `commands::boxes` already do, and add only one definition line per tool to `tools()` plus its dispatch. Keep tool descriptions short and precise, since every one costs tokens per message.

Don't add anything from part 1 (warp, notes, OCR box, cleanup, raw prep) or QC list tools (sibling branches do those).
