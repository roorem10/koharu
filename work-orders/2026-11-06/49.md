# WO-49: Vision model picks the font category and copies source effects

Noted during 0.0.3 testing, and it fits issue #52: a vision model could pick the lettering category per line and report the source lettering's look (bold, gradient, outline), so the result looks closer to the original without hand work.

Read first: `commands/context/reading.rs` (Read chapter's per-line labels), `commands/lettering.rs`, `crates/booharu-context/src/lettering.rs`, the category style settings, `components/editor/LetteringCategoryLine.tsx`.

Build:

1. Extend Read chapter's per-line output with optional source look fields: `bold`, `outline` (none, thin, thick, plus a rough color), and `fill` (solid or gradient, plus rough colors), each with a confidence, using native structured output. No new prompt path, no extra request. Stored on the line in the sidecar, like other labels.
2. Applying: on lines where it's confident, set the matching typography parts on top of the category style: bold, outline color and width as a share of font size, gradient colors for titles and SFX. Default dialogue stays plain unless the source clearly isn't. Off by default behind a setting **Copy the original's look** in Typesetting preferences, one undo step per page. Hand-styled boxes never change. Put the decision in a pure, tested function.
3. Show the reason in the box's style line, like "Outline: copied from original (model)".
4. No vision model: skipped quietly with the reason visible in the Ready check when that's available; on this branch just in the Read chapter result.
5. **Agent action:** read a line's source look, and apply it to chosen boxes.
